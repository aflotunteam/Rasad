1. AVVALGI TZDAGI ASOSIY KAMCHILIKLAR

1) MVP va sanoat versiyasi chegarasi aniq emas
Nima uchun muhim: Ikki kunlik xakaton vazifasi bilan to‘liq davlat tizimi aralashib ketadi.
To‘ldirish: MVP, Pilot va Production alohida belgilanadi.

2) Ma’lumotlar sifati nazorati yetarli emas

To‘ldirish: Data Quality moduli qo‘shiladi.

3) Subyektlarni identifikatsiyalash aniq emas
Nima uchun muhim: Bir korxona turli manbada turlicha yozilishi mumkin.
To‘ldirish: Entity Resolution mexanizmi kiritiladi.

4) Xavf kategoriyalari umumiy
Nima uchun muhim: “Yuqori xavf” nimani anglatishi noaniq.
To‘ldirish: Risk Taxonomy yaratiladi.

5) 0–39 / 40–69 / 70–100 chegaralari asoslanmagan
Nima uchun muhim: Ilmiy dalilsiz qat’iy chegara xato.
To‘ldirish: Chegaralar kalibrovka qilinadi.

6) Modelni qayta o‘qitish jarayoni yo‘q
Nima uchun muhim: Vaqt o‘tishi bilan model sifati pasayadi.
To‘ldirish: Model Lifecycle kiritiladi.

7) Model drift nazorati yo‘q
Nima uchun muhim: Iqtisodiy muhit o‘zgaradi.
To‘ldirish: Drift Detection moduli.

8) Ma’lumot kelib chiqishi kuzatilmaydi
Nima uchun muhim: “Bu raqam qayerdan keldi?” savoliga javob kerak.
To‘ldirish: Data Lineage.

9) API shartnomalari to‘liq emas
Nima uchun muhim: Integratsiyada xatolar chiqadi.
To‘ldirish: API versioning + schema.

10) Fon vazifalari mexanizmi yo‘q

11) Xatolarni boshqarish standarti yo‘q

12) Zaxira va tiklash ko‘rsatkichlari aniq emas
Nima uchun muhim: Favqulodda holatda tiklanish talab etiladi.

13) Monitoring yetarli emas
Nima uchun muhim: Tizim ishlamay qolishini kech bilish mumkin.

17) Axborotlarni saqlash muddati yo‘q

18) Insidentlarga javob berish tartibi yo‘q

19) Qabul mezonlari juda umumiy

3. XAVFLAR TASNIFI

RASADda xavf albatta turlarga ajratilishi kerak.

R08 — Kompleks xavf

48. RASADNING MAHSULOT SIFATIDAGI ANIQ TA’RIFI

RASAD — ko‘p manbali iqtisodiy ma’lumotlarni yagona muhitda qayta ishlab, subyekt, hudud va tarmoq kesimida g‘ayrioddiy holatlar hamda xavf signallarini aniqlaydigan, ularni ustuvorlashtiradigan, sabablarini izohlaydigan va ekspert qarorini qo‘llab-quvvatlaydigan intellektual tahlil platformasidir.

YAKUNIY MUHIM TUZATISH

Avvalgi TZda RASAD asosan:
“ma’lumot → model → xavf”
sifatida ko‘ringan edi.

Mukammal arxitekturada esa:
“ma’lumot sifati → subyektni aniqlash → belgilar → bir nechta model → kalibrovka → xavf → ishonch darajasi → tushuntirish → ekspert qarori → qayta aloqa → model monitoringi”
to‘liq zanjiri bo‘lishi kerak.

Shu to‘ldirishlardan keyin TZ endi faqat xakaton konsepsiyasi emas, RASADni haqiqiy davlat/korporativ darajadagi intellektual axborot tizimi sifatida ishlab chiqishga asos bo‘ladigan texnik spetsifikatsiyaga yaqinlashadi.
